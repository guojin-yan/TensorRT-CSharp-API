# TensorRtExec Trtexec Parity Matrix Artifact

This file mirrors `tensor-rt-exec-trtexec-parity-matrix.json` for quick review. It is a machine-readable release-readiness artifact, not runtime proof.

| ID | trtexec option | Status | Proof boundary |
|---|---|---|---|
| `onnx-input` | `--onnx` / `--model` / `--onnxFile` | implemented | ONNX parsing/build report is build-only unless a sample runner records real model execution. |
| `save-engine` | `--saveEngine` / `--save-engine` / `--engine` / `--plan` / `--engineFile` | implemented | Serialized engine creation is build evidence, not inference proof. |
| `load-engine` | `--loadEngine` | bounded-runtime-output | Current load-engine path records preflight/readback metadata and may execute bounded one-float-input enqueue/readback. Unmatched output is runtime-output-captured-unverified and is not real-model or package-consumer proof. |
| `dynamic-shape` | `--minShapes/--optShapes/--maxShapes` | implemented-report | Shape profiles in reports do not prove every dynamic shape ran correctly. |
| `shape-profile` | `--minShapes input:... --optShapes input:... --maxShapes input:...` | implemented-report | Profile configuration is not output correctness proof. |
| `shape-alias-batch` | `--shapes --inputShapes --batch` | implemented-report | Shape aliases and batch values are normalized/reportable migration aids; they do not prove binding coverage, dynamic profile execution, or output correctness. |
| `timing-iterations` | `--avgTiming / --minTiming` | implemented-builder-config-readback | `--avgTiming` uses the cross-version builder-config setter/readback; `--minTiming` uses the TRT8 legacy compatibility setter and remains parse-only on TRT10/11. This is builder evidence, not runtime proof. |
| `yolovision-owner-backfill-shape-profiles` | `--minShapes/--optShapes/--maxShapes per YOLOv8n task` | documented-report | Task-specific shape profiles are build/report evidence only; real-model-runtime requires YoloVision run log, output JSON, hashes, and owner review. |
| `fp16` | `--fp16` | wrapper-ready | The switch can be represented; GPU/model support must be proven by smoke. |
| `int8` | `--int8 --calib` | parse-report-only-calibration-boundary | INT8 and calibration cache paths are CLI/GUI/report fields only; calibrator ownership and cache validity are not promoted by this application matrix. |
| `precision-shortcuts-debug-boundary` | `--fp8 --best --dumpRefit --markDebug --dumpDebugTensors` | parse-report-only | FP8/best precision shortcuts, refit dumps, and debug tensor names remain CLI/GUI/report fields only. |
| `engine-packaging-refit-weight-streaming` | `--versionCompatible --excludeLeanRuntime --stripWeights --refit --allowWeightStreaming --weightStreamingBudget` | implemented-build-runtime-readback-with-version-guards | Official trtexec packaging/refit/streaming flags retain versioned set/readback semantics. The ONNX lifecycle is a separate managed extension. |
| `onnx-stripped-plan-refit-extension` | `TensorRtExec extension: --refitFromOnnx` | implemented-trt10-trt11-refit-lifecycle-with-version-guards | TRT10/11 cover stripped-plan deserialize, copied inventory, parser load, engine commit, context gate, and enqueue; TRT11 records a 10-value zero-mismatch unreviewed reference comparison. |
| `refitted-plan-persistence-extension` | `TensorRtExec extension: --saveRefittedEngine` | implemented-trt10-trt11-persist-dispose-independent-reload | Clears and reads back serialization `ExcludeWeights`, writes a distinct full-weight refitted plan, disposes the original engine, reloads a new owner, and routes local runtime through that owner. TRT11 additionally passes a loadEngine-only second process with identical output SHA. The separate local-feed PackageReference consumer is TRT10-only; public-feed, post-publish and release proof remain external. |
| `workspace-memory-pool` | `--workspace --memPoolSize` | implemented-build-readback | Known pool tokens are applied through the shared builder config and read back as requested/readback byte diagnostics; this is builder-config evidence only. |
| `deployment-policies` | `--device --useDLACore --allowGPUFallback --tacticSources --directIO --sparsity --stronglyTyped` | implemented-build-readback-with-version-guards | Device selection uses a dedicated host thread; builder flags, DLA core and tactic masks are read back. `sparsity=force` and TRT8 strongly typed remain parse-only; DLA model proof stays external. |
| `io-layer-precision-policies` | `--inputIOFormats --outputIOFormats --precisionConstraints --layerPrecisions --layerOutputTypes` | implemented-build-readback-with-version-guards | TRT10.11 applies and reads back FP32 linear I/O plus first-convolution rules. TRT11.0 validates matching FP32 I/O formats while removed precision setters remain parse-only. Both external YOLOv8n-cls runs pass a 1000-value reference comparison and export hashed detailed inspector JSON. TRT8 parser creation now has a native SEH/status boundary and isolated MNIST parse/build/enqueue evidence; TRT8 detailed layer-policy evidence remains uncollected. |
| `timing-cache` | `--timingCacheFile --exportTimingCache` | implemented-build-cache-lifecycle | Successful builds import/export through the typed `TensorRtTimingCache` owner and record byte counts/SHA256 in `TimingCacheArtifact`; this remains build-cache evidence, not runtime proof. |
| `gui-cli-field-map` | `CLI/WinForms parity checklist` | checklist-backed | GUI/CLI field parity proves option surface alignment only; command preview, GUI screenshots, dry-runs, and reports are not runtime proof. |
| `plugin-library-boundary` | `--plugins/--plugin/--dynamicPlugins/--setPluginsToSerialize` | diagnostic-alias-compatible | Plugin library paths, trtexec-compatible aliases, and copied inventory metadata do not prove plugin library load/register/deregister. |
| `bounded-benchmark-scheduler` | `--iterations --warmUp --duration --streams --infStreams --sleepTime --idleTime --avgRuns --percentile --threads --useSpinWait --useCudaGraph --noDataTransfers` | implemented-bounded-runtime | Independent context/bindings/stream owners execute bounded scheduling, real driver threads, event polling, bridge-owned start-delay event fan-out, graph capture/launch with fallback, and transfer suppression; no-transfer runs do not claim output correctness, and package-consumer proof remains external. |
| `profiling` | `--profilingVerbosity --dumpProfile --separateProfileRun --exportProfile --saveProfile` | implemented-report | Profiling artifacts are diagnostics unless a real enqueue run and log prove runtime execution. |
| `wait-idle-controls` | `--sleepTime --idleTime` | implemented-bounded-runtime | `--sleepTime` queues one bridge-owned native host-function delay and fans one event out to all inference streams; `--idleTime` is applied between measured rounds. Neither is model correctness proof. |
| `layer-dump` | `--dumpLayerInfo --exportLayerInfo` | implemented-inspector-readback | Real build/load-engine paths copy `TensorRtEngineInspector` layer data and can export it; `--profilingVerbosity=detailed` writes a self-describing JSON document and top-level `LayerInfoArtifact` length/SHA256, while other modes retain one-line text. Dry-run/dependency-unavailable paths remain report-only; inspector metadata alone is not output correctness proof. |
| `report-export-alias` | `--exportReport / --report` | implemented-report | Report aliases only choose JSON/Markdown output paths; reports remain build/report evidence and cannot promote runtime proof. |
| `verbose-logging` | `--verbose` | implemented-report | Verbose logs are supporting evidence only; logs need SHA256 and owner review. |
| `binding-metadata` | `--loadInputs --dumpOutput --dumpRawBindingsToFile --exportOutput` | implemented-structured-pointer-free-binding-report | Build, load-engine, and runtime reports expose top-level `BindingMetadata`; the external static YOLOv8n-cls record confirms implicit profile 0, two linear FP32 tensors, enqueue readiness, and structured output validation. YoloVision still owns task-specific semantics and model-proof promotion. |
| `package-consumer-runtime-proof-boundary` | release proof validator | local-refitted-plan-package-consumer-runtime-public-proof-owner-action-required | The current-Release local-feed PackageReference consumer passed restore/build/runtime and 53/53 strict checks. Public-feed and post-publish validation remain required for package-consumer-runtime promotion. |

Every entry keeps `isRuntimeProof=false` in the JSON. The package proof boundary row points to release validators; it does not allow `TensorRtExec` itself to declare release proof.
