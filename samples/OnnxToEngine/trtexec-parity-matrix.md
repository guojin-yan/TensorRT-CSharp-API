# OnnxToEngine trtexec Parity Matrix

`samples/OnnxToEngine/trtexec-parity-matrix.json` records how the sample aligns with key official `trtexec` model-conversion concepts. The goal is practical ONNX-to-engine coverage and reportability, not claiming a complete `trtexec` clone.

## Implemented Or Reported Areas

- Model paths: `--onnx`, `--saveEngine`, `--loadEngine`; `--loadEngine` now combines readonly readback with bounded one-float-input runtime output when shapes are concrete.
- Dynamic shapes: `--minShapes`, `--optShapes`, `--maxShapes`, `--shapes`, `--inputShapes`.
- Precision: `--fp16` implemented; `--fp8`, `--best`, `--int8`, and calibration remain parse/report-only or ownership-blocked until capability and model proof exist.
- Memory and builder controls: `--workspace` and known `--memPoolSize` pools are applied through `TensorRtBuilderConfig.SetMemoryPoolLimit` and immediately read back through `GetMemoryPoolLimit`. `--tacticSources`, `--directIO`, and `--sparsity=enable|disable` use typed set/readback; `--stronglyTyped` uses the TRT10 raw bit, relies on the TRT11 always-strongly-typed contract, and stays parse-only on TRT8. Timing cache uses the typed owner and records cache byte counts/SHA256 in the build report.
- I/O and layer policies: `--inputIOFormats` / `--outputIOFormats` validate `type:format[+format]` specifications and support one-spec broadcast or one spec per network tensor. TRT8/10 set and read back tensor types/formats, precision constraint flags, layer precision, and layer output types. Exact layer names beat wildcard rules and later rules override earlier rules. TRT11 can apply allowed formats only when the inferred tensor type already matches; removed constraint/layer setters remain explicit version-guarded parse-only options.
- Plugin diagnostics: `--plugins`, `--plugin`, `--dynamicPlugins`, and `--setPluginsToSerialize` are accepted as aliases/repeated lists and normalized into `Plugins`; they remain diagnostics and do not load, register, deregister, or serialize plugin libraries.
- Diagnostics and preflight: `--profilingVerbosity`, `--verbose`, `--previewOnly`, `--dryRun`.
- Runtime-shaped artifact switches: `--loadInputs` can feed bounded generic runtime. Successful output readback applies `--dumpOutput` to every output tensor, writes every tensor to `--exportOutput`, and writes deterministic engine-order float32 bytes plus a per-tensor offset/hash manifest for `--dumpRawBindingsToFile`. Capture without a reference match remains `runtime-output-captured-unverified`; it is not tensor correctness, real-model-runtime, or package-consumer-runtime proof.
- Bounded benchmark scheduler: compatible float engines apply `--iterations`, `--warmUp`, `--duration`, effective `--streams`/`--infStreams`, `--idleTime`, `--avgRuns`, `--percentile`, boolean `--threads`, `--useSpinWait`, `--useCudaGraph`, and `--noDataTransfers`. Each context owns its bindings/stream/events; threaded mode uses one driver thread per context, spin mode polls CUDA event readiness, graph mode captures/instantiates/launches with a recorded direct-enqueue fallback, and no-transfer mode performs neither input H2D nor output D2H/readback. `--sleepTime` remains parse-only because a CPU sleep would not match its device-side launch-gap semantics.
- Engine packaging and device policy: version-compatible, lean-runtime exclusion and refit flags use set/readback; TRT10/11 strip uses `StripPlan` plus the selected refit mode. `--saveRefittedEngine` is a managed extension that clears and reads back serialization `ExcludeWeights`, serializes the full-weight committed engine, disposes it, independently reloads the new plan, and gates runtime on copied metadata. A separate local-feed PackageReference consumer reproduces its output SHA without source assembly loading. Weight streaming uses official budget grammar and engine readback before context creation. TRT8 unsupported combinations remain explicit parse-only. Public-feed, post-publish and release proof remain external.

Build-only, parse-only, preflight-only, sidecar-only, dependency-probe-only, runtime-output-captured-unverified, and synthetic runtime reports are not real-model-runtime proof and not package-consumer-runtime proof.
