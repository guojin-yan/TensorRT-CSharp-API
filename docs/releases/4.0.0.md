# TensorRT-CSharp-API 4.0.0

发布日期：2026-08-10
版本类型：正式稳定版

`4.0.0` 是 TensorRT-CSharp-API 4 系列的首个正式稳定版本。该版本固定托管 API、项目自有原生 Bridge 包矩阵和第三方运行时边界，并以 `v4.0.0` Stable/Public GitHub Release、NuGet.org、GitHub Packages 和 API 文档站点作为公开交付入口。

## 主要变更

- 顶层命名空间统一为 `JYPPX.TensorRtSharp` 与 `JYPPX.CudaSharp`，共享的 TensorRT 能力归入 `JYPPX.TensorRtSharp`。
- 覆盖 engine 构建与加载、execution context、tensor/binding、动态 shape、日志、profiling、allocator、stream/event、CUDA Graph 和 CUDA RTC 等核心路径。
- 提供 TensorRtExec、OnnxToEngine、YoloVision 和分类等源码应用或示例，但它们不作为 NuGet 包发布。
- 演示模型记录固定来源、revision、license、获取与转换命令、输入输出契约和 SHA256；模型权重与 ONNX 保存在仓库外，不进入发布包或源码归档。
- NuGet 包使用 Apache-2.0 许可证表达式、`nuget/logo.jpg` 图标和根目录英文 README。

## 发布物

正式公开包集合固定为 19 个包：

- 1 个核心托管包：`JYPPX.TensorRT.CSharp.API`；
- 6 个 Windows x64 `.Bridge` 包；
- 12 个 Linux x64 `.Bridge` 包，覆盖 Ubuntu 20.04、22.04 和 24.04 的受支持组合。

19 个包发布到 NuGet.org 和 GitHub Packages，并作为 `.nupkg` 附加到 GitHub Release。GitHub Release 还包含仓库跟踪源码归档。

Bridge 包只包含项目编译的 `jyppxtrtbridge.dll` 或 `libjyppxtrtbridge.so`，不包含 CUDA、cuDNN、TensorRT 或 NVRTC。YoloVision、Classification、full-runtime、meta、collection 以及任何第三方运行时包均不在正式发布集合中。

## 兼容性与环境要求

- 使用者必须安装与 Bridge 包名一致的 CUDA、cuDNN 和 TensorRT，并安装兼容的 NVIDIA 驱动。
- Windows 与 Linux Bridge 包按 RID、发行版、TensorRT、CUDA 和 cuDNN 版本分别命名，不能跨不兼容的运行时组合混用。
- Ubuntu 20.04 Bridge 通过 GitHub-hosted Ubuntu 20.04 container lane 构建；Ubuntu 22.04/24.04 Bridge 通过 GitHub-hosted runner 构建。
- GitHub-hosted Linux runner 仅提供构建、打包和静态消费验证，不提供真实 NVIDIA GPU runtime proof。
- TensorRT engine 与生成它的 TensorRT、CUDA、GPU 和构建配置存在兼容性边界，不应在未验证的环境间直接复用。

## 升级注意

从 `4.0.0-preview.1` 升级时，将核心托管包和匹配的 `.Bridge` 包同时更新到 `4.0.0`。不再使用 full-runtime 或拆分的厂商依赖包；CUDA、cuDNN、TensorRT 和 NVRTC 由目标机器自行安装和维护。

由开发快照迁移时，应检查命名空间是否已归入 `JYPPX.TensorRtSharp` 或 `JYPPX.CudaSharp`，并删除对本地 `.nupkg`、仓库内 `ProjectReference` 或已退役运行时包的临时依赖。

## 验证范围与已知限制

- Release 构建、ProjectQuality、workflow contract、许可证、包内容和第三方运行时排除策略纳入正式发布前门禁。
- Windows 与 Linux 的 19 包矩阵必须由正式 workflow 从同一提交重新构建，不能直接复用旧提交的本地候选包。
- Windows 真实 runtime smoke 只对实际执行并保留日志、主机信息和 SHA256 的组合成立；不能从单一组合外推全部矩阵。
- Linux hosted lane 不含 GPU。Linux 真实 runtime proof 仍需后续在兼容 NVIDIA GPU 主机上采集。
- NuGet.org、GitHub Packages 和 GitHub Release 的公共 URL、下载 SHA256 与 clean external consumer 结果只能在正式发布完成后采集，发布前本地验证不能替代 post-publish proof。
