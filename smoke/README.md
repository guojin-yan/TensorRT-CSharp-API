# Smoke

This directory contains validation-oriented runner projects that we use for:

- package-consumer smoke
- release gates
- native loading checks
- TensorRT / CUDA feature regression coverage

These projects are intentionally different from the user-facing examples under `samples/`:

- `samples/` should focus on common adoption scenarios and readable reference cases.
- `smoke/` should focus on deterministic diagnostics, compact output, and CI-friendly validation.

## Notes

- Release and workflow documents should reference `smoke/` when describing validation runners.
- New end-user examples should go to `samples/`, not `smoke/`.
- `OnnxToEngineSmokeRunner` emits compact release-evidence markers for the deployment-critical ONNX-to-engine path: `BuilderPluginRegistry`, `GlobalPluginRegistryLookup`, `ParserDiagnosticSnapshot=`, `ParserDiagnosticSummary=`, `ParserRefitterDiagnosticSnapshot=`, `ParserRefitterDiagnosticSummary=`, `RuntimeDiagnosticSnapshot=`, `RefitterDiagnosticSnapshot=`, `ParserModelSupport`, `ParserUsedVCPluginLibraries Count=`, `LayerOutputIdentity=`, `EngineFileRoundTrip=True`, `StreamRoundTrip=True`, and `InferenceBindings Execution=`. These markers prove the high-level wrapper surface is callable and copied into managed values on the runner; they are not a substitute for a clean package-consumer runtime proof, Linux runner proof, or real external-model proof.
- `OnnxToEngineSmokeRunner` keeps dependency failures skippable with `Skipped=True Reason=...`. A skipped run is diagnostic evidence only and must not be promoted to release runtime proof.
- `PluginRegistryInventorySmokeRunner` emits `PluginRegistryInventoryDiagnostics` for builder/global/runtime plugin registry copied metadata. It proves only pointer-free creator and field inventory wrappers; it does not register plugins, create plugin instances, enqueue plugins, or replace package-consumer runtime proof.
